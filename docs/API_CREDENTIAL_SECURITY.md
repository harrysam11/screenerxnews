# API Credential Security Architecture & Vault Hardening (P10.2-C.2)

---

## 1. Overview

The Credential Vault (`backend/app/services/credential_vault.py`) safeguards third-party API keys, private RPC credentials, and Bearer tokens. In P10.2-C.2, the cryptographic layer was hardened with persistent installation-unique salts, metadata tracking, encrypted recovery packages, and strict zero-plaintext database backup boundaries.

---

## 2. Core Security Guarantees

1. **Zero Plaintext Storage**:
   No unencrypted secret is ever written to SQLite, flat configuration files, or logs.
2. **Authenticated Symmetric Envelope Encryption**:
   Secrets are encrypted using AES-128-CBC with HMAC-SHA256 authenticated envelope encryption via Python's `cryptography.fernet.Fernet`.
3. **SEC-04: Unique Persistent Cryptographic Salt**:
   - Each installation generates an independent $\ge 32$-byte cryptographic salt saved to `./data/.vault_salt` with strict `0600` POSIX permissions.
   - Derivation metadata is persisted alongside in `./data/.vault_meta.json` with `0600` permissions (specifying KDF algorithm, iterations, hash function, and version).
   - **Dual-Salt Decryption Fallback**: The vault supports seamless backward-compatible decryption for legacy credentials encrypted with previous default salts, eliminating migration disruption.
4. **PBKDF2HMAC Key Derivation**:
   Master keys are derived using PBKDF2 with SHA-256 and 100,000 iterations against the installation's persistent salt.
5. **Key Management & Storage Security**:
   The master key is read from `settings.CREDENTIAL_VAULT_KEY` or loaded from `./data/.vault_key` (persisted with `0600` permissions on disk).
6. **SEC-05: Vault Backup & Encrypted Recovery Package Isolation**:
   - Database backups (`sqlite3.Connection.backup()`) **never** bundle master keys (`.vault_key`) or salt files into the database.
   - Key recovery is performed exclusively via encrypted recovery packages (`.vaultpkg`) generated by `SQLiteBackupService.export_vault_recovery_package()`.
   - Packages are symmetrically encrypted using Fernet keys derived from user-supplied passphrases (PBKDF2, 100,000 iterations).
7. **SEC-06: Endpoint Protection**:
   Provider configuration and credential APIs require local loopback invocation or authentication via `ADMIN_API_TOKEN` (`X-API-Key` or `Authorization: Bearer <token>`).
8. **Redaction & Leakage Prevention**:
   - Secret preview displays only the first 4 and last 4 characters (`sk-l...6789`).
   - URLs automatically strip sensitive query parameters (`?key=...`, `&token=...`) and path tokens (`/v2/<token>`).
   - Diagnostic logging and exception handlers recursively sanitize sensitive dictionary keys.
9. **Deterministic Key Fingerprinting**:
   A deterministic SHA-256 fingerprint preview (first 16 characters) is generated for each secret, allowing operators to verify key identity without decrypting the secret.
10. **Immediate Revocation**:
    Revoking a credential sets `is_revoked = 1` and logs an immutable audit event, preventing any future decryption or transmission.

## 3. Storing an Encrypted Credential

```bash
curl -X POST http://127.0.0.1:8000/api/v1/providers/prov-custom-solana/credentials \
  -H "Content-Type: application/json" \
  -H "X-API-Key: $ADMIN_API_TOKEN" \
  -d '{"secret": "sk-live-9876543210abcdef9876543210", "credential_type": "api_key"}'
```

Response:
```json
{
  "status": "SUCCESS",
  "credential": {
    "id": "cred-a1b2c3d4e5f6",
    "provider_id": "prov-custom-solana",
    "credential_type": "api_key",
    "key_fingerprint": "9f83c12d4a5b6e7f",
    "redacted_preview": "sk-l...3210",
    "is_revoked": 0,
    "created_at": "2026-11-14T18:20:00Z"
  }
}
```
The raw plaintext secret is never returned in any response.
